# Техническое задание и трассировка реализации

Документ связывает исходное ТЗ с кодом: что сделано, где лежит, что осталось.
Формулировки требований сохранены, к каждому добавлен статус и место в проекте.

Легенда: ✅ сделано · ◐ сделано частично · ⛔ вне MVP.

## 1. Общие сведения

**Рабочее название:** OnPage SEO Assistant — расширение для быстрого технического и
контентного SEO-аудита текущей веб-страницы.

**Цель:** за несколько секунд проанализировать открытую страницу, найти основные
on-page проблемы, показать ошибки/предупреждения/информацию, объяснить причину,
предложить исправление, подсветить проблемный элемент и экспортировать отчёт.

**Браузеры:** Chrome, Яндекс Браузер, Opera и другие Chromium с Manifest V3.

**Границы:** анализ текущей страницы, а не всего сайта. Вне MVP: позиции в выдаче,
обратные ссылки, полноценный краулер, интеграция с Search Console, автоисправление HTML,
серверная база, обязательный внешний API.

> SEO Score — внутренняя диагностическая оценка расширения, а не оценка позиции
> страницы в Google или Яндексе. Эта оговорка выводится в UI и во всех экспортах.

### Идентификаторы правил

ID стабильны и никогда не переиспользуются — они попадают в экспортированные отчёты.
Всего реализовано **85 правил**.

| Префикс | Диапазон | Категория Score |
|---|---|---|
| `META-001…007, 015…017` | title, description | `meta` |
| `META-008, 009, 018…022` | canonical, hreflang | `canonical` |
| `META-010, 014` | viewport, favicon | `technical` |
| `META-011` | html lang | `meta` |
| `META-012, 013` | robots-директивы | `indexing` |
| `HEAD-001…010` | заголовки | `headings` |
| `LINK-001…012` | ссылки (010, 011 — только после сетевой проверки) | `links` |
| `IMG-001…010` | изображения | `images` |
| `SD-001…006` | структурированная разметка | `schema` |
| `SOC-001…008` | Open Graph, Twitter | `social` |
| `CNT-001…005` | контент | `content` |
| `TECH-001…007` | локальные технические | `technical` |
| `TECH-008…010, 012` | robots.txt, X-Robots-Tag, sitemap (сетевые) | `indexing` |
| `TECH-011` | цепочка редиректов (сетевая) | `technical` |

Полные тексты — в `src/locales/ru.json` и `src/locales/en.json`, ключи `rules.<ID>.{t,d,r}`.

## 4. Архитектура

Стек: TypeScript, React 18, Vite 5, Manifest V3, Vitest, ESLint, Prettier.
Playwright для e2e заявлен в ТЗ, но в текущую версию не включён.

Структура и обязанности компонентов, поток сообщений и модель данных описаны в
[CLAUDE.md](../CLAUDE.md) — там же инвариант «ядро не знает про DOM».

Отклонение от структуры из ТЗ: локали лежат в `src/locales/*.json` (единый источник для
UI и текстов правил, доступен в юнит-тестах), а `public/_locales/` содержит только
строки уровня манифеста — имя и описание расширения.

## 5. Оценка и приёмка

### Веса категорий

| Категория | Вес |
|---|---|
| Индексация и robots | 25 |
| Title и Description | 20 |
| Заголовки | 15 |
| Canonical и hreflang | 10 |
| Ссылки | 10 |
| Изображения | 8 |
| Structured Data | 7 |
| Social Meta | 3 |
| Контент | 2 |

`Score = clamp(100 − Σ штрафов, 0, 100)`. Error −5…−15, Warning −1…−5, Info 0.
Штраф правила растёт с числом совпадений, но ограничен двукратным базовым значением.
Отдельно выводятся Technical / Content / Social. Таблица штрафов —
`src/core/scoring/weights.ts`, тест на пример из ТЗ (100−8−5−2−1−1=83) —
`tests/unit/scoring.test.ts`.

### Критерии приёмки MVP

Все пункты выполнены, кроме проверки в реальных Opera и Яндекс Браузере — она требует
ручного прогона на стенде. Расширение не использует API за пределами общего для
Chromium набора, поэтому блокирующих различий не ожидается.
