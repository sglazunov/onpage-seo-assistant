# Анализ аналогичных расширений и что из этого взято

Обзор сделан перед реализацией, чтобы не изобретать заново набор проверок и UX-паттерны,
которые уже проверены на практике в популярных SEO-расширениях.

## Кто изучался

| Расширение | Аудитория | Сильная сторона | Что мешает |
|---|---|---|---|
| **Detailed SEO Extension** (Glen Allsopp) | ~450 000+ пользователей, Chrome + Firefox | Мгновенная сводка: title, description, meta robots, canonical, indexability, hreflang, структура заголовков, Open Graph, Twitter, Schema; быстрые ссылки на robots.txt и sitemap. Без логина и внешнего API | Нет числовой оценки, нет экспорта отчёта, нет подсветки элементов на странице |
| **SEO Pro Extension** (MarketingSyrup) | ~80 000+ пользователей | Всё on-page в одной панели: title, description, canonical, meta robots, word count, полевые Core Web Vitals, уведомления о редиректах, все meta/link/script-теги | Слабая работа с изображениями и ссылками, нет истории |
| **SEO Minion** | Массовый | On-page анализ, проверка битых ссылок, валидация hreflang, предпросмотр SERP-сниппета, сравнение выдачи по локациям | Часть функций требует сети и работает медленно; интерфейс перегружен |
| **SEOquake** (Semrush) | Массовый | Diagnosis-отчёт, SERP-оверлей, данные по домену, экспорт | Ключевые отчёты уводят на сайт сервиса; много внешних запросов |
| **Robots Exclusion Checker** | Технические SEO | Визуальные алерты по шести сигналам: robots.txt, meta robots, AI-боты, X-Robots-Tag, canonical, UGC/nofollow. Симуляция Googlebot / Googlebot News / Bing / Yahoo, цветовая индикация директив | Узкая специализация: только индексация |
| **Lighthouse** (встроен в Chrome DevTools) | Разработчики | Официальные категории SEO, Performance, Accessibility, Best Practices — эталонный список технических проверок | Тяжёлый, долгий прогон, не заточен под быстрый ежедневный осмотр |

## Что взято в проект

**Из Detailed SEO** — принцип «одна панель, ноль настроек, ноль логина»: аудит стартует
автоматически при открытии popup (`autoRunOnOpen`), никаких аккаунтов и внешних API.
Оттуда же — набор базовых сигналов и быстрые ссылки на robots.txt / sitemap.xml
(вкладка «Техническое»).

**Из Robots Exclusion Checker** — идея, что индексируемость это не один флаг, а
композиция сигналов. У нас на вкладке Meta есть отдельный блок «Индексируемость»,
который сводит meta robots + googlebot + yandex, а сетевой проход добавляет
X-Robots-Tag и правило robots.txt, реально блокирующее текущий URL
(`src/background/robots.ts`, правила `TECH-008`, `TECH-009`). Категория `indexing`
получила максимальный вес 25 — именно потому, что это самый дорогой класс ошибок.

**Из SEO Pro** — счётчик слов, разбор script-тегов (async / defer / блокирующие) и
уведомление о редиректах. Реализовано в `ResourceStats` и `TECH-005` / `TECH-011`.

**Из SEO Minion** — проверка HTTP-статусов ссылок и валидация hreflang. Проверка
статусов вынесена в отдельную кнопку с прогрессом и ограничением параллелизма,
потому что именно она в аналогах чаще всего подвешивает интерфейс
(`src/background/link-checker.ts`). Hreflang даёт правила `META-020..022`, включая
самую частую реальную ошибку — отсутствие self-reference.

**Из Lighthouse** — облегчённый набор технических проверок как ориентир: viewport,
charset, размер DOM, mixed content, блокирующие скрипты. Полноценный Lighthouse не
встраивается: он решает другую задачу и стоит секунды прогона.

## Чего в аналогах нет, а у нас есть

1. **Детерминированный Score с разбором по категориям** и честной формулировкой,
   что это внутренняя диагностика, а не прогноз позиций. В аналогах либо оценки нет
   вовсе, либо она не объясняется. Каждый балл прослеживается: `scoreImpact` у issue
   складывается в категорию, категория — в группу, группа — в общий балл.
2. **Подсветка элемента прямо на странице** с прокруткой, цветом по категории и
   выходом по Esc. Реализована оверлеями в shadow DOM, то есть CSS страницы не
   трогается (`src/content/highlighter.ts`).
3. **Экспорт в четыре формата** (JSON / CSV / Markdown / автономный HTML-отчёт) плюс
   копирование сводки. У большинства бесплатных аналогов экспорта нет.
4. **Отличие `alt` отсутствующего от `alt=""`.** Почти все аналоги считают пустой alt
   ошибкой, хотя для декоративных изображений это корректная разметка. У нас это
   разные правила с разной серьёзностью (`IMG-001` warning против `IMG-002` info).
5. **Настраиваемые пороги и отключаемые правила.** Длина title/description — не закон
   поисковых систем, поэтому пороги вынесены в настройки, а любое правило можно
   заглушить, и оно перестанет влиять на Score.
6. **Русский интерфейс как первоклассный**, а не машинный перевод: `default_locale`
   в манифесте — `ru`, стоп-слова частотного анализа покрывают русский и английский.

## Продуктовые выводы, повлиявшие на архитектуру

- **Сетевые проверки нельзя делать частью основного аудита.** В аналогах это главная
  причина тормозов. У нас основной проход полностью локальный и синхронный по DOM, а
  всё сетевое — по явной кнопке, с запросом host-разрешения в момент клика.
- **Минимальные разрешения при установке.** Вместо `<all_urls>` в `permissions`
  используется `activeTab` + `scripting` с инъекцией по требованию, а доступ к сайтам
  запрашивается опционально и только для сетевых проверок. Это заметное отличие от
  аналогов, которые просят полный доступ сразу при установке.
- **Ядро аудита отделено от DOM.** Content script только собирает `PageData`; правила
  и скоринг — чистые функции. Поэтому весь набор правил покрывается юнит-тестами без
  браузера, чего в аналогах, судя по их поведению на граничных страницах, нет.
