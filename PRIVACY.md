# Политика конфиденциальности — OnPage SEO Assistant

Дата последнего изменения: 7 августа 2026 года.

## Коротко

Расширение работает полностью локально в вашем браузере. У проекта нет сервера, нет
аккаунтов и нет аналитики. Разработчик не получает никаких ваших данных.

## Какие данные обрабатываются

При запуске аудита расширение читает DOM активной вкладки и формирует отчёт: мета-теги,
заголовки, ссылки, изображения, структурированную разметку, видимый текст и статистику
ресурсов. Эти данные существуют в памяти popup, пока он открыт.

## Что сохраняется

В `chrome.storage.local` (локальное хранилище браузера) сохраняются:

- настройки расширения;
- история аудитов, если она включена: URL, заголовок страницы, дата, Score и количество
  проблем. **Содержимое страниц в историю не попадает.**

История отключается и очищается в настройках расширения. При удалении расширения все
эти данные удаляются вместе с ним.

## Что расширение НЕ делает

- не отправляет HTML или текст страниц на какой-либо сервер;
- не собирает и не передаёт пароли;
- не читает содержимое полей ввода и форм;
- не читает и не передаёт cookie;
- не собирает историю посещений;
- не загружает и не выполняет удалённый JavaScript;
- не использует внешние аналитические сервисы, рекламные сети и трекеры;
- не продаёт и не передаёт данные третьим лицам.

## Сетевые запросы

**Основной аудит не отправляет данные на сервер расширения. Отдельные ресурсы страницы,
например изображения и `og:image`, могут загружаться самим браузером по исходным URL.**

Сбор данных со страницы и расчёт отчёта выполняются локально. Сервера у расширения нет
вообще, поэтому отправлять данные некуда.

Загрузка ресурсов происходит на вкладках «Изображения» и «Social», где показываются
миниатюры картинок и предпросмотр Open Graph-карточки. Как правило, эти файлы уже лежат
в кэше страницы, которую вы открыли. Запросы отправляются с
`referrerPolicy="no-referrer"`, поэтому адрес расширения сайту не передаётся. Если
`og:image` размещён на стороннем CDN, запрос уйдёт к этому CDN.

Остальные сетевые запросы выполняются только по вашему явному нажатию кнопки. Адреса
проверяемых ссылок передаются напрямую целевым сайтам — так же, как если бы вы открыли
эти ссылки сами. Запросы идут к:

- `robots.txt` и `sitemap.xml` домена анализируемой страницы;
- URL самой анализируемой страницы — чтобы прочитать HTTP-статус, заголовок
  `X-Robots-Tag` и цепочку редиректов;
- адресам ссылок, найденных на странице, — чтобы проверить их HTTP-статус.

Запросы идут напрямую с вашего браузера на эти адреса, без промежуточных серверов, и
отправляются без учётных данных (`credentials: 'omit'`) — то есть без ваших cookie. У
каждого запроса есть таймаут (10 секунд для ссылок, 8 секунд для robots.txt и sitemap),
а количество одновременных запросов ограничено настройкой (по умолчанию 6, максимум 10).

## Разрешения и зачем они нужны

| Разрешение | Назначение |
|---|---|
| `activeTab` | Доступ к текущей вкладке в момент, когда вы открыли расширение |
| `scripting` | Внедрение скрипта сбора данных в текущую вкладку по запросу |
| `storage` | Локальное хранение настроек и истории |
| `downloads` | Сохранение экспортируемых отчётов на ваш диск |
| `http://*/*`, `https://*/*` (опционально) | Только для сетевых проверок. Запрашивается отдельно в момент нажатия кнопки и может быть отозвано в настройках браузера |

Полный список разрешений — в `public/manifest.json`. Других разрешений расширение не
объявляет: `permissions` содержит ровно четыре записи из таблицы выше, а доступ к сайтам
лежит в `optional_host_permissions`, то есть при установке браузер его не запрашивает.

Опциональное разрешение не запрашивается при установке. Если вы его не выдадите, всё
остальное расширение продолжит работать — недоступны будут только сетевые проверки.

## Экспорт отчётов

Файлы экспорта (JSON, CSV, Markdown, HTML) формируются в браузере и сохраняются на ваш
диск. Они никуда не отправляются. Отчёт может содержать данные проанализированной
страницы, поэтому будьте внимательны, если делитесь им.
